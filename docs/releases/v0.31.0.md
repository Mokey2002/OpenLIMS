# v0.31.0 — Workflow assignments and notifications

Directors can configure actions for each workflow step in the frontend:

- Assign its work item to a named active administrator or technician.
- Notify the assignee and/or up to 50 additional named users in the application.
- Combine these actions with existing result or measurement activation conditions.

For example, make a review step depend on step 1, configure concentration below 10,
select an assignee, and enable notification. Only a matching, eligible step activates.
This assigns the work item; QC approval still requires the existing reviewer permissions.

## Execution and access

Action settings are copied into each run. Later template edits affect new runs only.
Assignment requires current sample modification permission; notifications require current
sample visibility and an active account. Failed eligibility checks leave work unassigned or
skip recipients and are recorded in `WORKFLOW_ACTIONS_APPLIED` audit events. Assignment never
grants project membership. Notification text includes English and Spanish and links to the sample.

Actions, notifications, work creation, and audit writes share the workflow transaction.
Repeated synchronization does not notify again for an already activated step. An explicit
retry creates a new work item, rechecks access, and sends a new notification. A user selected
as both assignee and additional recipient receives only one alert per activation.

## Deployment and validation

Run `python manage.py migrate` before restarting the updated API and workers. Migration
`pipelines.0005` adds empty-default JSON action settings to template steps and run steps;
existing templates and runs keep their behavior and receive no retroactive assignments.

All 46 targeted backend tests passed and cover branch outcomes, pinned actions, permissions, deactivation,
deduplication, retries, validation, and rollback. Local backend tests use SQLite schema
synchronization with migrations disabled; PostgreSQL migration and concurrency validation
remain required before deployment. Frontend build and changed-file lint checks passed.
The Playwright designer save/edit test uses mocked API responses. Browser execution is pending:
Chromium was unavailable locally and the browser download failed with timeouts/HTTP 502.

## Scope

This release supports named users and step-activation notifications only. Team scheduling,
email delivery, completion/overdue triggers, configuration-package transfer, and general
automation rules remain future work. Existing notifications retain their stored content;
this release does not add retrospective redaction after membership changes.
