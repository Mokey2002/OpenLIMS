# v0.33.0 — Notebook and report layouts

## Notebook template designer

Open **Laboratory Notebook → Templates**, create a reusable template from the standard
structure or current experiment, then choose **Edit structure**. Notebook writers can edit
its name and description, add headings, rich text, protocol steps, checklists, tables,
structured results and calculation records, and duplicate, reorder or remove blocks.
Save the structure, then choose **Use template** to create an experiment.

Changes affect future experiments. Existing experiment blocks and immutable revisions remain
intact. The editor sends `expected_updated_at`; the server locks the template during updates
and rejects a stale timestamp. Close the editor and reload the page before retrying a conflict.
API clients may also supply that timestamp. Change events record before/after SHA-256
fingerprints rather than private template content. Read-only collaborators cannot edit, delete
or instantiate templates. Inactive templates cannot create experiments through either API path.

## Report layouts

The existing saved **REPORT** templates now work in **Reports**, **Comparisons** and
**Investigations**. Directors manage templates; authenticated users select available templates.
Configure the heading, embedded PNG logo, footer, Letter/A4 paper, orientation, summary
visibility and summary placement before/after the data. On analysis screens, also configure
chart visibility and placement before/after the tables. Preview uses synthetic data matching
the current report screen and does not save a template or generate an audited artifact.

Project/compliance summaries show matching audit-event counts. Comparison and investigation
summaries show the analysis narrative. Scope, template revision, evidence tables, method notes,
limitations and provenance remain mandatory. Tables wrap to the selected page width, charts
scale to fit, headers repeat across pages and truncated tables carry a CSV export notice.

PDF export proposals freeze the selected template configuration and revision. Confirmation
still recalculates evidence and access, and the artifact retains the frozen configuration.
CSV exports retain their existing format. Selecting **Built-in layout** retains the previous
PDF layout. No database migration is required for this release.

## Validation

- Backend tests cover notebook permissions, stale edits, experiment preservation, inactive
  templates, configuration validation, synthetic PDF rendering and frozen confirmed exports.
- Browser checks cover saving/reloading notebook sections and selecting/previewing a report
  template for investigation PDF export, alongside existing customization checks.
- Frontend production build, changed-file ESLint and migration consistency checks.
- Synthetic portrait and landscape PDFs generated for all three report types; representative
  first and last pages visually inspected for wrapping, pagination, chart fit and footers.

Local backend tests use SQLite with schema synchronization. PostgreSQL migrations and the
full deployment test suite remain CI validation gates.
