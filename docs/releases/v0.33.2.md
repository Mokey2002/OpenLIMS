# v0.33.2 — Page navigation recovery

Older tabs can retain references to page files removed by a frontend deployment. Previously,
a failed lazy import could leave a blank page until the user refreshed manually.

All lazy pages now use a common loader that recognizes module/chunk and CSS preload failures.
It attempts one automatic document reload per release and tab, preserving the destination URL.
It skips automatic recovery if the user has navigated elsewhere or session storage is unavailable.
The retry marker persists across reloads to prevent repeated reloads when the failure persists.
Other exceptions are handled by a page error boundary without automatic reloads.

The page outlet has its own loading and error boundaries, keeping the navigation shell visible.
Persistent errors provide English/Spanish messages and actions to reload or return to My Work.
Normal navigation continues without a document reload. No backend or schema changes.

Validation includes browser scenarios for normal navigation, a missing page module, and a
persistent module failure. The missing-module scenario reproduced a blank page before the fix.
This confirms recovery for that failure mode; the user's deployed browser error was not captured.
