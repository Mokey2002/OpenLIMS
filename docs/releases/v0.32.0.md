# v0.32.0 — Saved workspace views and print templates

## My Work customization

- Show or hide summary, assigned work, overdue, and attention widgets.
- Choose work, sample, status, QC, and due-date columns; columns follow selection order.
- Filter the currently loaded assigned-work list by text and status. Summary counts retain
  their original meaning and are not recalculated from these display filters.
- Save named personal views or director-managed views shared with a role. Users can select
  shared views but cannot edit another owner's or role-shared configuration.
- Configurations are stored in the database; the selected view ID is remembered per user in
  the browser. Selecting the built-in layout restores the default widgets and columns.

This release customizes My Work, not every application screen. It does not provide arbitrary
widgets, a visual page builder, or field-level security. Existing APIs still enforce access.

## Print templates

Directors manage named templates on Reports and Barcode Labels. Other authorized users select
an available template before generating the usual confirmed artifact. Template creation,
editing, and archival are audited, and stale edits are rejected using the revision number.

Supported controls:

- Heading, footer, and embedded PNG logo (200 KB and 1000 pixels maximum).
- US Letter or A4 paper.
- Compliance report portrait/landscape orientation and optional event-count summary.
- Label grids of one/two columns and three/four/five rows; optional project code and borders.
- Downloadable PDF preview containing only synthetic data, without saving a template or
  creating sample labels, reprint counters, or audit events.

The selected template's settings and revision are frozen in the pending action and artifact
parameters. Later edits or archival do not change that frozen layout. Sample access is still
rechecked on confirmation. Template selection does not change barcode identity or reprint
tracking. Oversized barcodes are rejected rather than squeezed below the supported bar width;
select a one-column layout if necessary. Embedded ReportLab fonts avoid machine-dependent
font substitution. Label headings, project codes, and footers have limited printed space.

Custom report layouts currently apply to compliance/audit PDFs, not comparison reports,
investigation packages, notebook exports, or CSV files. Audit columns, scope/date metadata,
provenance, and page numbers remain present. PDFs show up to 250 audit events with an explicit
truncation notice; use CSV for the full filtered export. No arbitrary HTML or remote logo URLs
are accepted. Physical printer calibration and barcode scan testing remain deployment tasks.

## Deployment and validation

Apply `python manage.py migrate` before restarting the updated API and workers. Migration
`settings_app.0005` creates workspace-view and print-template tables. No existing laboratory
records or template settings are rewritten.

Validation: 27 backend tests passed (permissions, revisions, snapshots, PDF generation, and
existing settings/report/label behavior). Five browser tests passed with mocked API responses,
including the prior workflow-action regression. Frontend build/lint and visual PDF review also
passed. Local backend
tests use SQLite schema synchronization with migrations disabled. PostgreSQL migrations and
the full integration suite must pass CI before release.
